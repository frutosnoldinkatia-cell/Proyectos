================================================================================
                      RASTREO PY - ROLES Y PERMISOS
                           Borrador v1 (2026-10-11)
================================================================================

Este documento define quién puede hacer qué en la plataforma. Es la referencia
para el backend (rutas /api) y para el frontend (pantallas y botones).
Si algo no está permitido acá, el sistema debe bloquearlo en AMBOS lados.


[ 1. ROLES ]
--------------------------------------------------------------------------------
CIUDADANO
  Cualquier persona que se registró y verificó su correo (código OTP).
  Es el rol por defecto al registrarse.

ADMINISTRADOR
  Personal autorizado que modera la plataforma. No se puede obtener desde el
  registro: se crea solo con el script crear-admin.js (variables
  ADMIN_IDENTIFICADOR y ADMIN_PASSWORD).

SIN SESIÓN (no es un rol, es la ausencia de uno)
  Persona que entra a la página sin iniciar sesión. El ingreso es
  obligatorio: sin sesión solo puede registrarse, verificar el código e
  iniciar sesión. La API responde 401 a todo lo demás.


[ 2. REGLA DE LAS PISTAS ]
--------------------------------------------------------------------------------
- Para enviar una pista hay que tener sesión iniciada (ciudadano o admin).
  Motivo: evitar pistas falsas o basura sin nadie responsable detrás.
- La pista se publica como ANÓNIMA: el público nunca ve quién la envió.
- El sistema guarda internamente qué usuario la envió. Solo un
  administrador puede verlo, y solo para moderar abusos.
- Una pista solo se muestra al público después de que un administrador
  la VALIDA. Las pendientes y rechazadas no son públicas.

[ 5. CÓMO SE APLICA ]
--------------------------------------------------------------------------------
Backend (la protección real):
  - Rutas de ciudadano: middleware authenticate  -> 401 si no hay sesión.
  - Rutas de admin:     middleware requireAdministrator -> 403 si es ciudadano.
  - El rol se lee siempre del token/servidor, nunca de lo que mande el navegador.
Frontend (la experiencia):
  - Un único guard en navigateTo() que use esta tabla.
  - El menú se arma según el rol del usuario actual.

Respuestas estándar:
  401 = no iniciaste sesión          403 = no tenés permiso para esto
