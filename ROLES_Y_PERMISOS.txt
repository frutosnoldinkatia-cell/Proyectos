================================================================================
                      RASTREO PY - ROLES Y PERMISOS
                           Borrador v1 (2026-10-11)
================================================================================

Este documento define quién puede hacer qué en la plataforma. Es la referencia
para el backend (rutas /api) y para el frontend (pantallas y botones).
Si algo no está permitido acá, el sistema debe bloquearlo en AMBOS lados.


[ 1. ROLES ]
--------------------------------------------------------------------------------
CIUDADANO
  Cualquier persona que se registró y verificó su correo (código OTP).
  Es el rol por defecto al registrarse.

ADMINISTRADOR
  Personal autorizado que modera la plataforma. No se puede obtener desde el
  registro: se crea solo con el script crear-admin.js (variables
  ADMIN_IDENTIFICADOR y ADMIN_PASSWORD).

SIN SESIÓN (no es un rol, es la ausencia de uno)
  Persona que entra a la página sin iniciar sesión. Puede CONSULTAR: feed,
  fichas públicas, mapa, pistas validadas y estadísticas. Para cualquier
  ACCIÓN (reportar, enviar una pista, ver "Mis casos" o alertas) tiene que
  ingresar; la API responde 401 a esas rutas.
  (Decisión del equipo, opción A, alineada con el PDF del Workshop,
  sección 5.2. Reemplaza al "ingreso obligatorio para leer".)


[ 2. REGLA DE LAS PISTAS ]
--------------------------------------------------------------------------------
- Para enviar una pista hay que tener sesión iniciada (ciudadano o admin).
  Motivo: evitar pistas falsas o basura sin nadie responsable detrás.
- La pista se publica como ANÓNIMA: el público nunca ve quién la envió.
- El sistema guarda internamente qué usuario la envió. Solo un
  administrador puede verlo, y solo para moderar abusos.
- Una pista solo se muestra al público después de que un administrador
  la VALIDA. Las pendientes y rechazadas no son públicas.

[ 4. PANTALLAS DEL FRONTEND ]
--------------------------------------------------------------------------------
  Pantalla      Sin sesión            Ciudadano           Admin
  ------------  --------------------  ------------------  -------------------
  home / feed   visible               visible             visible
  stats         visible               visible             visible
  lead (pista)  redirige a login      visible             visible
  report        redirige a login      visible             vuelve al inicio con aviso
  my-cases      redirige a login      visible             vuelve al inicio con aviso
  alerts        redirige a login      visible             visible
  admin         redirige a login      "Acceso denegado"   visible
  auth / otp    visible               redirige a home     redirige a home

  - Los botones y enlaces a una pantalla no permitida NO se muestran
    (no alcanza con bloquearlos al hacer clic). Excepción: sin sesión SÍ se
    muestran Reportar, Enviar pista, Mis casos y Alertas; al tocarlos llevan
    al login y, después de ingresar, vuelven a la pantalla pedida.
  - El botón de demo "Vista Administrador" se elimina.


[ 5. CÓMO SE APLICA ]
--------------------------------------------------------------------------------
Backend (la protección real):
  - Rutas de ciudadano: middleware authenticate  -> 401 si no hay sesión.
  - Rutas de admin:     middleware requireAdministrator -> 403 si es ciudadano.
  - El rol se lee siempre del token/servidor, nunca de lo que mande el navegador.
  - Lectura pública (GET /api/casos, /casos/:id, /casos/:id/foto, /pistas,
    /pistas/:id/fotos/:n y /estadisticas): sin sesión, con límite por IP
    (LIMITE_LECTURA_PUBLICA_POR_MINUTO, por defecto 3000: en el Workshop
    ~100 celulares salen por la misma IP).
  - Qué NO sale nunca en la lectura pública: casos PENDIENTE o RECHAZADO,
    LOCALIZADO fuera de VENTANA_LOCALIZADOS_HORAS, pistas no validadas, quién
    envió una pista, número de denuncia, próximo seguimiento, checklist del
    admin, motivo de rechazo o cierre y contacto del reportante. El número de
    denuncia lo ven solo quien reportó el caso ("Mis casos") y el admin.
Frontend (la experiencia):
  - Un único guard en navigateTo() que use esta tabla.
  - El menú se arma según el rol del usuario actual.

Respuestas estándar:
  401 = no iniciaste sesión          403 = no tenés permiso para esto
